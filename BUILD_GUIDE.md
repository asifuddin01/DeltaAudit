## Part A — The project (improved brief)

### A1. One-paragraph pitch

Recent benchmarks have shown that deep models for predicting transcriptional responses to *unseen* genetic perturbations do not beat simple baselines (Ahlmann-Eltze, Huber & Anders, *Nature Methods* 2025). They have also shown that standard metrics overstate skill, because much of what looks like a good prediction is really the *systematic* shift shared by most perturbed cells (Viñas Torné et al., *Systema*, *Nature Biotechnology* 2025). This project does **not** claim either finding as new. It runs **a pre-registered, leakage-checked replication audit** of both findings on a large public CRISPRi Perturb-seq screen, with every baseline computed here rather than cited. It then adds a test the earlier papers did not run: **a controlled test of whether a gene-graph prior helps, and whether that help comes from the graph's biological *content*.** The prior model is compared with a no-prior twin and with an identical graph whose gene labels have been shuffled.

### A2. Names

- **Repo, Python package and CLI:** `deltaaudit` (Δ is the expression change being predicted; "audit" because this checks published claims)
- **Write-up title (fixed):** *What the metric hides: predicting unseen gene knockdowns*
- Optional subtitle for the write-up: *A pre-registered audit of systematic variation, linear baselines and gene-graph priors on held-out CRISPRi perturbations*

### A3. Research questions and pre-registered hypotheses

| ID | Question | Hypothesis (direction fixed before test data are scored) | Primary test |
|---|---|---|---|
| **Q1** | How much of the headline score is the average perturbation effect? | **H1:** On raw PearsonΔ, the *train-mean* baseline scores within 0.05 of the best model. Its per-perturbation score is strongly correlated (Spearman ρ > 0.5) with that perturbation's cosine similarity to the mean effect. | Paired bootstrap, best model vs. mean, raw PearsonΔ |
| **Q2** | Is there any perturbation-specific skill? | **H2:** Under the perturbation-specific (Systema-style) metric, the linear baseline is > 0 but far below the split-half noise ceiling. | Bootstrap CI of linear pspec-PearsonΔ vs. 0 |
| **Q3** | Does a learned non-linear model add anything over linear? | **H3:** MLP (no prior) is *not* significantly better than ridge-linear. | Paired bootstrap + Holm |
| **Q4** | Does a gene-graph prior add anything? | **H4a:** GNN + GO graph beats the MLP without a prior. **H4b:** GNN + real GO beats GNN + label-shuffled GO, which shows the gain comes from biological content rather than from graph smoothing as such. | Paired bootstrap + Holm |

A null on H3 or H4 is a valid, publishable result. The write-up reports whatever the pre-registered tests return. Pre-registration is written in Phase 3 and committed **before** any model is scored on test perturbations.

### A4. A note on causal language

A GO similarity graph is not a causal graph. The *causal-inference* content of this project is **interventional generalization**: predicting the effect of an intervention (a knockdown) that the model never saw. The graph is a *structural prior* about which interventions should have similar effects. The write-up says "structural/gene-graph prior". It says "causal prior" only for the optional directed TF→target network (CollecTRI) arm, and even there with care. This is also the bridge to the thesis model (HCGT-PG): this project is its first, smallest empirical test.

### A5. What "done" means (the finish line)

The entry is finished when the write-up states, with every number generated by code:

1. A computed score for **every** baseline (no-change, train-mean, ridge-linear, linear+GO, kNN-GO; additive on doubles), on every metric, with 95% CIs.
2. **One diagnosed failure of the headline metric**: the train-mean baseline's raw PearsonΔ, its correlation with systematic variation, and the ranking change under the perturbation-specific metric.
3. **A significance test**: paired bootstrap over held-out perturbations with Holm correction across the pre-registered family.
4. One-command reproduction from a clean clone, pinned data checksums and a passing test suite.

## Part B — Key design decisions (already made, and the reasons)

| Decision | Choice | Why |
|---|---|---|
| Primary dataset | **Replogle 2022 K562 essential CRISPRi**, GEARS-processed (`replogle_k562_essential`) | Roughly 1,000+ distinct single-gene knockdowns after GEARS filtering. That gives hundreds of held-out perturbations per fold, far above "dozens". Public, CPU-sized once pseudobulked. |
| Doubles / additive baseline | **Norman 2019 K562 CRISPRa** (GEARS `norman`): 105 single-gene and 131 two-gene perturbations | The only standard dataset with doubles. Also used as a single-gene replication. CRISPRa, so effects are activation rather than knockdown, and this must be stated. |
| Optional replication | **Virtual Cell Challenge 2025, H1 hESC CRISPRi** (300 perturbations; official 150/50/100 train/val/test split; ~15 GB training h5ad) | An independent cell type with an *official* held-out set. Stretch goal only (Day 8). |
| Thesis data | Hook provided (`configs/datasets/thesis_template.yaml`) | Use it **only if** a thesis dataset has more distinct perturbations than Replogle K562 essential. Claude Code asks the user once, in Phase 0. |
| Unit of modelling | **Pseudobulk per perturbation** (mean log-normalized expression), Δ = pert − control | All baselines in the literature predict mean shifts. This makes everything CPU/Mac-sized (≈1,100 × 5,000 matrix). |
| Unit of statistics | **Held-out perturbation** (never cells or genes) | Cells within one perturbation are not independent evidence about generalization to new perturbations. |
| GPU | **Probably unnecessary.** Small nets on ~1k examples train in seconds on CPU or Apple MPS. A Colab T4 notebook is provided for the full grid if the Mac is slow, and for an optional GEARS reference run. | Your constraint: GPU only if unavoidable. |
| GNN implementation | **Pure PyTorch sparse matmul** (SGC/GCN style); no PyTorch Geometric | PyG installs on Apple Silicon are fragile, and nothing here needs PyG. |
| Prior graph | GO annotation Jaccard kNN graph (GEARS-style), built from the **official GO GAF**. The GEARS `gene2go_all.pkl` is a fallback only. | Avoids unpickling a downloaded file, pins a dated GO release, and stays comparable to GEARS. |
| Null for the prior | **Gene-label permutation** of the same graph (3 permutations), plus degree-preserving edge swap as a secondary null | Keeps the topology identical and breaks only the gene↔node mapping. This isolates *content*. |

### C2. Download and integrity rules

- `deltaaudit download <dataset>` streams to `data/raw/<dataset>/`, with each archive in its **own new, empty directory**. Extract with `tarfile`'s `filter="data"` (or an equivalent zip path-traversal check). Never execute anything from `data/raw/`.
- On first download, compute SHA-256 and write it to `data/checksums.sha256` (commit this file). Every later run calls `deltaaudit verify`, which **fails hard** on a mismatch.
- `data/SOURCES.md`: URL, datafile ID, date downloaded, size, SHA-256, licence/citation for each asset.
- `data/raw/` and `data/processed/` are git-ignored. Small derived artefacts (split files, pseudobulk parquet < 50 MB) may be committed or attached to a release.

### C3. Mac memory rules

- Open every h5ad with `anndata.read_h5ad(path, backed="r")` and compute pseudobulks **per perturbation in chunks**. Never call `.toarray()` on the full matrix.
- After pseudobulking, the working data is tiny: (n_perts × n_genes) float32 ≈ 1,100 × 5,000 × 4 B ≈ 22 MB.
- VCC (18,080 genes × ~300k cells) must be processed backed and chunked. Budget 30–60 min of CPU.

### C4. Processed artefacts (per dataset, in `data/processed/<dataset>/`)

| File | Content |
|---|---|
| `pb_mean.parquet` | Rows = perturbations (incl. `ctrl`), cols = genes; mean log-normalized expression |
| `pb_half_A.parquet`, `pb_half_B.parquet` | Same, from a seeded random 50/50 split of each perturbation's cells (noise ceiling) |
| `delta.parquet` | `pb_mean − pb_mean.loc['ctrl']` |
| `meta.parquet` | Per perturbation: target gene(s), n_cells, guide id(s) if present, is_double, target_in_expression_genes, target_knockdown_log2fc |
| `genes.parquet` | Gene symbol, Ensembl id if available, is_hvg |
| `ctrl_embed.parquet` | Genes × 32 PCA embedding of the gene–gene correlation in **control cells only** (no perturbation information, so it is safe to compute once) |
| `MANIFEST.json` | Input SHA-256s, code git hash, config, timestamp, row/col counts |

QC applied and logged: drop perturbations with < 30 cells (configurable). Report how many were dropped and why. Report the knockdown efficiency distribution (target-gene log2FC). Optionally flag perturbations with weak knockdown, but do **not** silently drop them.

## Part D — Splits and leakage guards

### D1. Split design

- **Outer CV:** 5 folds over *perturbations* (seeded). Every perturbation is in the test set exactly once, so pooled across folds there are ~1,000+ paired test observations for Replogle.
- **Inner validation:** 10% of each fold's training perturbations, used for early stopping and for choosing ridge λ / PCA K. **The test fold is never used for any selection.**
- **Norman:** 5 folds over single genes. A held-out gene's doubles are excluded from training (*strict*). The doubles analysis uses a separate split: test doubles whose two singles are both in training (the "seen 2/2" setting).
- **VCC (optional):** the official split (train 150 → our train/val; official validation + test 150 → our test).
- Splits are saved to `data/splits/<dataset>/fold_<k>.json` with `train`, `val`, `test` lists, and committed.

### D2. Leakage assertions (in `tests/test_splits.py`, and also called at runtime before any fit)

1. `set(train_genes) ∩ set(test_genes) == ∅`, where a double contributes **both** of its genes.
2. If guide IDs exist: `set(train_guides) ∩ set(test_guides) == ∅`. (Replogle essential uses one dual-guide construct per gene, so gene-disjointness implies guide-disjointness. Document this in the data card.)
3. `ctrl` is in no test set.
4. Every quantity fitted from data (μ_train, PCA gene embeddings, ridge weights, scaler stats, kNN-GO neighbour averages) receives **only** `train` (+`val`) perturbation indices. Enforce this by passing index arrays, and add a test that corrupts test rows with NaN and checks that training still succeeds and is unchanged.
5. Folds partition the perturbation set exactly (union = all, pairwise disjoint).

### D3. Known, documented leakage that is *not* fixed (limitations section)

- GEARS chose the HVG panel using all cells, including test-perturbation cells. Optional sensitivity check (Day 8): re-select HVGs from control + training cells only, on one fold, and show the conclusions are unchanged.

## Part E — Models

Notation: Δ ∈ ℝ^{P×G} (perturbations × genes). μ = mean of Δ over **training** perturbations. All models output Δ̂_q for a held-out perturbation q.

### E1. Baselines (CPU, minutes)

| ID | Name | Prediction |
|---|---|---|
| B0 | **No-change (control)** | Δ̂_q = 0 |
| B1 | **Train-mean** | Δ̂_q = μ |
| B2 | **Ridge-linear (Ahlmann-Eltze style)** | Gene embedding E = top-K PCs of Δ_trainᵀ (genes × K). Fit Δ_train ≈ E W P_trainᵀ + b by ridge, where P = rows of E for each perturbation's target gene. Predict Δ̂_q = E W E[q]ᵀ + b. Defaults K = 10, λ = 0.1. **Claude Code must check these against `benchmark/src/` in `github.com/const-ae/linear_perturbation_prediction-Paper` and match their formulation; record any deviation.** |
| B2-GO | **Ridge-linear + GO** | As B2, but P comes from a K-dim spectral embedding of the GO graph (Laplacian eigenvectors), which exists even for targets not in the expression panel |
| B3 | **kNN-GO** | Δ̂_q = mean of Δ over q's k nearest *training* perturbations in the GO graph (Jaccard-weighted); fall back to μ if none. Tests whether any prior gain is just neighbour averaging. |
| B4 | **Additive** (Norman doubles only) | Δ̂_{A+B} = Δ_A + Δ_B |

**Common support rule.** B2 needs the target gene to be in the expression panel. Primary analysis: perturbations whose target is in the panel (every model can predict). Secondary analysis: all perturbations, with B2 falling back to μ. Report both counts.

### E2. Learned models (one architecture, with and without the prior)

All learned models are **residual over the mean**: Δ̂_q = μ + f(q). The learned part is then explicitly the "beyond the average effect" part.

Input node features X (for every gene in the union of panel genes and target genes):
- E_Δ: K=32 PCA embedding of Δ_trainᵀ (train-only, so it is recomputed per fold)
- E_ctrl: K=32 PCA embedding of gene–gene correlation in **control cells only**
- a `missing` indicator for genes outside the panel (features zero)

| ID | Model | f(q) |
|---|---|---|
| M1 | **MLP (no prior)** | h_q = X[q] → MLP(256, GELU, dropout 0.2, 2 layers) → ℝ^G |
| M2 | **GNN + GO prior** | H = Â² X W₀ (SGC, 2 hops; Â = sym-normalized GO kNN adjacency with self-loops) → h_q = H[q] → the same MLP head |
| M3 | **GNN + shuffled GO** (×3 permutations) | As M2, with the graph's node labels randomly permuted (same topology) |
| M3b | GNN + degree-preserving rewired GO (secondary null) | As M2, with a double-edge-swap rewired graph |
| M4 (optional) | GNN + CollecTRI (directed TF→target, symmetrized) | As M2, with a different prior |

Training: MSE on Δ over training perturbations; AdamW, lr 1e-3, weight decay 1e-4; up to 300 epochs; early stopping on inner-validation **pspec-PearsonΔ** (patience 30); full batch, since there are only ~1k examples. **5 seeds × 5 folds** per model. Score each seed separately; the per-perturbation score used in statistics is the **mean over seeds**.

GO graph construction: for each gene, take its set of GO terms (all aspects, excluding `IEA` evidence as a config option). Jaccard similarity to every other gene; keep the top k = 20 neighbours with Jaccard ≥ 0.1; symmetrize. Report node coverage (fraction of target genes with ≥ 1 edge) and stratify results by "has a GO neighbour among training perturbations".

Expected runtime: < 1 min per run on an M-series CPU or MPS, so ~125 runs in under 2 h. Phase 6 measures this first. If the projection is > 3 h, use the Colab notebook.

### E3. Optional reference: GEARS itself (Colab T4, stretch)

Run `cell-gears` on Replogle K562 with **our** fold-0 split (via a custom split), one seed, so that a published model sits on the same axes. Report it as a reference point only; it is not part of the pre-registered family.

## Part F — Evaluation

### F1. Metrics (per test perturbation p, over evaluation genes; the target gene is **excluded** from every metric)

```
μ       = mean(Δ[train])                       # systematic effect (train-only)
raw_r   = pearson(Δ̂_p, Δ_p)                    # "PearsonΔ", the headline metric
raw_r20 = pearson on top-20 genes by |Δ_p|
mse, mse20
pspec_r = pearson(Δ̂_p − μ, Δ_p − μ)            # perturbation-specific (Systema-style)
          # if std(Δ̂_p − μ) < 1e-8 (e.g. B1): set to 0.0 and flag `degenerate=True`
pspec_r20 = pearson on top-20 genes by |Δ_p − μ|
dir20   = mean(sign(Δ̂_p) == sign(Δ_p)) on top-20 by |Δ_p|
pspec_dir20 = mean(sign(Δ̂_p − μ) == sign(Δ_p − μ)) on top-20 by |Δ_p − μ|
centroid_acc = 1[argmin_{p'∈test_fold} ||Δ̂_p − Δ_p'||₂ == p]      # Systema centroid accuracy
pds     = normalized rank of ||Δ̂_p − Δ_p|| among {||Δ̂_p − Δ_p'||}, 0 = best, 0.5 ≈ chance
          # ties → average rank
```

Sensitivity variant: replace μ by the centroid of **all** perturbations (closer to Systema's own definition, which uses the centroid of perturbed cells as the reference) and show the conclusions do not change.

### F2. Ceilings and diagnostics (computed once per dataset)

- **Split-half noise ceiling:** `ceil_raw(p) = pearson(Δ^A_p, Δ^B_p)` and `ceil_pspec(p) = pearson(Δ^A_p − μ, Δ^B_p − μ)`, from the half-split pseudobulks. Plot the model scores against this ceiling.
- **Systematic variation:** `sys_cos(p) = cos(Δ_p, μ_all)`. Plot its histogram (Systema quantified systematic variation this way).
- **The diagnosed failure (required deliverable):** for B1, report (i) mean raw_r; (ii) Spearman ρ between B1's per-perturbation raw_r and sys_cos; (iii) the full model ranking under raw_r vs. pspec_r, and which pairs flip; (iv) one annotated example perturbation with a high raw_r and ~0 pspec_r.

### F3. Statistics

For each pre-registered comparison (model A vs. B, metric m):

```
d_p   = score_A(p) − score_B(p)        # per test perturbation, pooled over 5 folds, seed-averaged
obs   = mean(d)
CI95  = percentile bootstrap, 10,000 resamples of perturbations (seeded)
p     = two-sided bootstrap p from the null-centred d: (1 + #{|mean(d*−obs)| ≥ |obs|}) / (B + 1)
also: Wilcoxon signed-rank p (secondary), median d, fraction of perts with d > 0
Holm  across the primary family (below); report raw and adjusted p
```

Sensitivity: a **cluster bootstrap** that resamples GO-similarity clusters (Leiden or agglomerative on the GO graph) instead of single perturbations. Knockdowns of genes in the same complex are not independent evidence.

**Primary family (Holm, α = 0.05). The metric is pspec_r unless stated.**

| # | Comparison | Hypothesis |
|---|---|---|
| C1 | best learned model vs. B1, on **raw_r** | H1 (headline inflation) |
| C2 | B2 vs. B1 | H2 (any specific skill) |
| C3 | M1 vs. B2 | H3 |
| C4 | M2 vs. M1 | H4a |
| C5 | M2 vs. M3 (mean of 3 perms) | H4b |
| C6 | B2-GO vs. B2 | prior in a linear model |

Secondary (reported, not Holm-gated): every model on every metric, B3, M3b, M4, the Norman replication and the VCC replication.

### F4. The validation ladder (reporting frame)

> **User action:** replace these rung names with the ladder from your scoping review so this project becomes its empirical companion. The code reads rungs from `configs/ladder.yaml`, so renaming them needs no code change.

| Rung | Criterion | Evidence |
|---|---|---|
| L0 Integrity | Checksums verified; leakage tests pass | `deltaaudit verify`, `pytest` |
| L1 Fit | Raw score reported with CI | Table 1 |
| L2 Beats no-change | Model > B0 (raw_r, mse) | Table 1 |
| L3 Beats the mean | Model > B1 on **pspec_r** | C2/C3 |
| L4 Specific signal | pspec_r CI excludes 0; reported as a fraction of the noise ceiling | F2 |
| L5 Beats linear | Model > B2 on pspec_r | C3 |
| L6 Prior content matters | M2 > M3 | C5 |
| L7 Replicates | Same sign on a second dataset/cell type | Norman / VCC |

## Part H — Phase-by-phase build (each phase ends with green tests and a commit)

### Phase 0 — Kick-off (Day 1, 1 h)
- Ask the user **one** question: "Do you want to use a thesis dataset instead of Replogle K562 essential? If yes, give its path/format and its number of distinct perturbations." Default is Replogle.
- Scaffold the repo, `pyproject.toml`, Makefile, CI, empty modules, `CLAUDE.md` and this file.
- **Accept:** `make test` runs (even with zero tests), and `git init` + first commit are done.

### Phase 1 — Data acquisition and integrity (Day 1)
- Implement `download`, `safe_extract`, `checksums`, `verify`. Download Replogle K562 essential, Norman and the GO GAF.
- Write `data/SOURCES.md` and a dataset card (cells, perturbations, genes, controls, knockdown efficiency).
- **Accept:** `make verify` passes, a corrupted byte makes it fail (tested on a temp copy), and the card is committed.

### Phase 2 — Pseudobulk, ceilings, diagnostics (Day 2)
- Backed, chunked pseudobulk; half-split pseudobulks; `delta.parquet`; `meta.parquet`.
- Compute sys_cos and the split-half ceilings on **all** perturbations. This is descriptive, contains no model, and is safe before pre-registration.
- First figure: the sys_cos histogram plus the ceiling distribution.
- **Accept:** pseudobulk equals a dense recomputation on the tiny fixture (test), and peak RAM is < 8 GB (log it).

### Phase 3 — Splits, leakage guards, PRE-REGISTRATION (Day 2)
- Splits per D1; every assertion in D2 as a test and as runtime checks.
- Write `reports/preregistration.md`: hypotheses (A3), the primary family (F3), the primary metric (`pspec_r`), α, bootstrap B, seeds, exclusion rules, the common-support rule, and what counts as a null. **Commit it and tag it `prereg`** before Phase 4 scores any test fold.
- **Accept:** `pytest tests/test_splits.py tests/test_leakage.py` is green, and the `prereg` tag exists.

### Phase 4 — Metrics and simple baselines (Day 3)
- `metrics.py` with unit tests on hand-built vectors. Known answers include: a perfect prediction gives r = 1 and pds = 0; B1 gives `pspec_r = 0` with the degenerate flag; a constant prediction gives centroid_acc at the chance level; the target gene is excluded.
- B0, B1 on all folds → `results/summary/baselines.csv`.
- **Accept:** tests are green, and the first computed numbers for B0/B1 exist.

### Phase 5 — Linear, prior baselines, additive (Day 4)
- GO graph (`go_graph.py`) with tests: symmetric, no self-edges before the self-loop step, coverage reported, permutation preserves the degree sequence.
- B2 (check against the const-ae script on the tiny fixture where possible), B2-GO, B3. On Norman, B4 for doubles plus B0/B1/B2 on singles.
